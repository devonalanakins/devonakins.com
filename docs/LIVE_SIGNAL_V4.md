## Evidence and data boundaries

- Editor: actual focused-edit timestamp, 120-second expiry. Automatic local matching of the built-in VS Code Git API's origin remote to the fixed public catalog. No filenames, paths, command output or Git metadata are sent. Unknown remotes produce no project name. SecretStorage credential lasts 30 days, remains revocable, and startup remembers explicit Resume/Pause consent without inventing an edit. Initial pairing stays paused. Codespaces using VS Code's Git API can use the same companion; its real host still requires acceptance.
- Participating remote work: persistent workspace identity (one fixed approved project and source, 30 days) can create separate 24-hour task identities. Each task has its own random token, ordered checkpoints, terminal state and revocation. Evidence expires after 120 seconds. One source/task ending cannot end another. A running remote task never proves human presence.
- GitHub: only catalog-mapped public push/PR/release event kinds, approved project names, time and official repository URL. Commit messages, authors and task titles are never projected. History never establishes active coding. Reuses the existing five-minute GitHub provider cache, cooldown and failure classification. Account-wide event sampling may be delayed or incomplete.
- Spotify: the existing account-level PKCE OAuth, encrypted D1 credentials, refresh rotation leases, 60-second provider cache, rate-limit cooldown and independent consent are retained. Adds bounded progress/duration metadata. Original artwork, Spotify attribution and links remain. Local progress stops at duration or evidence expiry. Paused/204/private/ad playback clears current track. Playback alone cannot establish development activity. No audio playback.
- GPT: the homepage is disconnected with scope personal Work/Codex. No supported authorized website feed has been verified. Historical profile captures remain dated, owner-published estimates in `/gpt/`. Existing opt-in observation bridge remains separately gated and is not promoted as an independently verified provider total.

## Participating runner connection

Open `/owner/presence/` through the existing Cloudflare Access boundary, then **Connected workspaces**. Choose the trusted environment and an approved public project, connect, and save the one-time displayed token into that runner's private secret settings as `DEVON_ACTIVITY_SOURCE_TOKEN`. It is source/project scoped and has no owner, Spotify, GPT or database privileges. Copy/hide works on phones and credentials clear when the page is hidden. Do not save this credential in source, issues, chats or public logs.

Instrument the runner's normal execution once:

```sh
node scripts/activity-run.mjs -- npm test
```

The wrapper starts a separate task, emits throttled checkpoints only when the real child process produces output, then completed/failed/cancelled on exit. No output contents leave the runner; no timer fabricates activity for silent commands. Telemetry failure cannot prevent the requested command. Commands longer than two minutes without observable progress become stale. Repository origin metadata is matched locally to the fixed public catalog and checked against source scope before any task is created. Unknown repositories do not report. Source metadata binds project selection when no Git metadata is available. For one runner shared across projects, `DEVON_ACTIVITY_SOURCE_TOKENS` may hold a private JSON map of approved project slug to its source token; the wrapper selects the correct credential automatically and removes both credential variables from the child environment. Ordinary runs need no repeated pairing or manual project choice. A participating Work/Codex runner can invoke the same wrapper; there is no verified provider-wide background hook for arbitrary conversations/tasks. This session did not install a credential into such a runner.

## Mobile-first GitHub Actions reporter — signed identity (2026-11-10)

The existing `Verify website` workflow executes on GitHub infrastructure whenever code is pushed to `main`, including changes made from a phone. On trusted main pushes, the runner now requests a **short-lived GitHub OIDC identity** scoped to `https://devonakins.com/github-actions-activity-v1`, not a reusable `DEVON_ACTIVITY_SOURCE_TOKEN` GitHub secret. The separate `npm test` step for pull requests and other branches does not invoke a reporter.

The Worker verifies the GitHub RSA signature with GitHub's pinned public JWKS endpoint, validates the exact GitHub repository and immutable account/repository IDs, workflow ref, main branch, push event, audience, expiry and hosted runner, then independently confirms the referenced GitHub Actions run is **currently in progress**. Any provider/network failure, invalid claim, ambiguous source, wrong project or completed run fails closed. GitHub OIDC subjects changed format in 2026; the signed immutable ID claims are authoritative and neither old nor new human-readable subject templates alone authorize a report.

The entry route `POST /api/activity/tasks/github-oidc-start` is **disabled by default** through `GITHUB_OIDC_ACTIVITY_ENABLED`. It returns 404 until explicitly enabled on the serving Cloudflare version. Even after activation, it also requires the existing unrevoked `github-actions` project-scoped reporter source, its sharing approval, the current public-work opt-in and global publication approval. Successful verified identity creates only a normal, bounded `activity_tasks` record. All subsequent running/terminal updates continue using the existing 24-hour ephemeral task token, 20-second nonterminal cooldown and 120-second freshness limit. No new database schema, GitHub App or reusable GitHub reporter secret is needed.

The local wrapper never passes the OIDC request credentials/JWT to a child process, CI output or public telemetry. A failed reporting request logs only a fixed failure category and **cannot cause a passing test command to be treated as a verified activity event**. Likewise, a CI run may pass even if its activity reporter is unavailable; inspect the source-specific acceptance evidence. GitHub commits/history are independently sourced and are not evidence that someone is currently coding.

**Release acceptance:** exact-head tests, signed-claim negatives and in-memory D1 integration checks, build and browser checks; protected main-branch merge and manual `v4` Worker release by exact SHA; explicit private Cloudflare activation of `GITHUB_OIDC_ACTIVITY_ENABLED=true`; then a genuine main push and verification that production D1 receives a fresh task and `/api/activity/v4` shows it only while current. Existing owner/source privacy gates and the `/_health` deployment verification remain mandatory. The feature's presence in a draft branch or an installed VS Code extension is **not** a live connection.

Phone-first limitation: this tracks **real main-branch GitHub Actions work**, not arbitrary ChatGPT mobile conversations or Work tasks that have no participating authenticated reporter. Codex IDE, Spotify, Threads, GitHub App repository discovery and personal GPT profile statistics each retain their separate authorization and supported-source boundaries.

## Authenticated agent-turn bridge — source-only candidate

The optional `scripts/agent-activity.mjs` adapter accepts **one already-authorized root turn's authenticated async event stream** from a private controller. It uses the *current* concurrent `/api/activity/tasks/start` and `/api/activity/tasks/signal` routes rather than the older singleton cloud pairing API. The controller—not this adapter—must authenticate to the provider, create and submit the turn, subscribe to events, inspect the saved terminal outcome after network interruptions, and independently verify any generated artifacts or tests.

Call `reportAgentTurnActivity({ events, projectSlug, sourceToken })` only from the trusted controller. Choose one `codex` or `chatgpt-work` scoped workspace connection through the owner Access page, then inject its one-time token into the runner's private secret storage as `DEVON_ACTIVITY_SOURCE_TOKEN` (not GitHub source's token and never in source, issues, logs or public markup). The adapter rejects nonallowlisted projects and a task start that reports the wrong source, project, token format, or expiration.

The reporter maps only a root-turn terminal event to `completed`, `failed`, or `cancelled`; it preserves `waiting` versus resumed `running` when genuine provider events arrive after the backend's 20-second nonterminal cooldown. Long-running progress checkpoints require *real incoming events*, not a repeating timer. It transmits only fixed state, optional null checkpoint, sequence number and UTC observation time. It ignores provider event bodies, prompts, session IDs, error messages, tool output, API usage totals and source paths. `completed` means **the provider turn ended**—not that source code, CI, deployment, or a user-facing task succeeded.

A stream error, early EOF, delivery failure or missing credential does not synthesize a verified completed or failed turn. Unconfirmed reporting errors use a fixed private warning marker. The already-created task then expires from the public/live projection after 120 seconds without fresh evidence. The adapter uses the existing 24-hour task identity under a 30-day revocable workspace source, with no new DB schema, Worker deployment or public-release permission. Existing GPT profile analytics remain disconnected.

**Acceptance still required:** validate the exact provider event contract from a genuine authorized root turn, wire this adapter into an actual private dispatcher, perform a source-scoped connection/revocation test, and verify a real pause/resume/terminal sequence with short-lived data. Fixture-driven tests of this source-only adapter do **not** establish a working autonomous ChatGPT account feed or true Work/Codex usage analytics. The earlier [PR #52](https://github.com/devonalanakins/devonakins.com/pull/52) was written against the legacy singleton bridge and should not be merged as-is over this V4 integration.

## API and retention

- `GET/HEAD /api/activity/v4`: same-origin, no-store aggregate, no credentials. Fresh editor, independent tasks, permitted Spotify, catalog history and disconnected GPT contract. Existing endpoints remain compatible.
- `GET/POST/DELETE /api/presence/owner?channel=tasks`: Access-owner boundary plus same-origin mutations. Lists sanitized source metadata and private projections; creates sources, toggles source publication, revokes source or task. Creation is bounded to 32 sources.
- `POST /api/activity/tasks/start`: legacy source bearer token; returns an independent task token; 64-task storage cap and 20-second source start cooldown.
- `POST /api/activity/tasks/github-oidc-start`: disabled-by-default signed main-branch GitHub Actions identity; requires matching owner-approved source, returns the same scoped task token; no reusable GitHub reporter secret.
- `POST /api/activity/tasks/signal`: task bearer token; fixed keys/enums, timestamps, sequence, CAS and 20-second nonterminal update cooldown. Terminal tasks cannot restart. State writes fence source revision and global generation.

Credential hashes only, no provider IDs or free text. Expired/revoked/generation-invalid reporter metadata is removed opportunistically. Tasks expire after at most 24 hours and sources after 30 days. Expired task rows may remain inert until the next source connection or task start; storage remains capped. Global stop invalidates reporter generation, clears disclosure and fences delayed responses. Private mode remains in effect until explicitly cleared. Each public source also requires existing global approval, owner opt-in, source approval and project allowlist. Deployment does not turn those gates on.

## Migration, backup and rollback

`0007_activity_tasks.sql` creates two dedicated tables and one index. It does not modify existing Spotify, editor or cloud singleton data. Before applying: inspect the active serving Worker binding, ensure it is the dedicated private D1 with replication off, obtain a Time Travel bookmark, verify migrations 0001–0006 and take boolean-only connection/privacy state counts. Apply the SQL once and register the exact filename in `d1_migrations` within the reviewed migration operation. Verify table SQL, counts and original connection/gate booleans afterward. Never copy OAuth ciphertext into logs.

Application rollback: redeploy the previous fully bound serving Worker version through the established production procedure. Leave the additive tables in place; old code does not reference them. No down migration or data deletion is needed. Revoke new sources before rollback if any have been paired. Time Travel restore is a recovery operation requiring review because restoring the whole database can rewind Spotify credentials; it is not the normal rollback path.
