### Core experiential promise

The website should feel like entering the mind of a working independent developer: portrait and personality first, then a genuinely informative living software ecosystem. The immersive 3D system should progressively expand from a small, understandable network into a large, explorable and historically replayable structure. Every visible object or signal should resolve to a documented type, owner, relationship and evidence state.

Visitors must be able to determine, without a manual:
- who Devon is, and what he writes, researches and builds;
- what approved work is genuinely active versus idle/stale/unavailable;
- what music is playing **when separately consented**;
- how verified projects and components fit together;
- which events represent development work, release/build history or verified deployments;
- what evolved historically, and which structures are current/dormant/retired;
- where to find meaningful project, writing and research details.

A public site is for public-safe personal storytelling, software provenance and exploration. It is not a public operations control plane.

### Real-time and persistence contract

Existing V4 same-origin aggregate `/api/activity/v4` is the allowed source for activity, via the existing `src/live-signal-client.ts` refresh mechanism. Do not duplicate source polling. Honor the global Stop All, private override, source consent, explicit project allowlists, expiration, revocation and in-flight privacy fencing. An event without source identity or fresh evidence does not animate.

Permanent graph history is a separate additive, server-authoritative and versioned model:
- `GraphEntity`: stable ID, type, owner/project, approved display label, source/evidence, publication state, first_seen, effective_at, retired_at, layout version.
- `GraphRelation`: stable ID, typed direction, source/target refs, evidence, effective_at/retired_at, publication state.
- `GraphChange`: idempotency key, effective date, action (create/update/retire/reinstate), verified evidence reference, schema version. Historic records are append-only.
- `ActivityEvent`: authenticated source, fixed event type, approved project/edge IDs, observed_at, expires_at, consent generation, source status. Ephemeral and separate from structural history.

Automatic ingestion must not conflate commit count with feature growth. Qualified graph changes can come from reviewed manifest/release records, approved schema metadata, verified deployment/integration contract changes. Changes are accepted privately, classified, then separately approved for public display. A new repository may be privately discovered but must never become a public project without owner approval.

Position encodes project family/domain -> owning system -> component type -> declared relationship. Stable slots persist between visits. A 3D volume's size reflects documented component count and relationships, not a fictitious productivity or health score. Pre-aggregate node groups and preserve identity in LOD. The atlas should support long-term growth without visually relocating every existing branch.
