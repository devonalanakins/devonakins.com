# Living Mind V5 R20 — Volumetric Public Atlas

Status: DRAFT / REVIEW ONLY. Stacked after R19 PR #74; the approved visual reference remains the source of truth. The protected V4 production release is unchanged.

## Implemented scope

This increment makes the central Three.js Signal Field a denser, depth-layered composition instead of eight isolated primitive icons:

- Eight abstract architectural clusters positioned exactly at the eight pre-approved public catalog identities.
- Each identity receives nine identical-in-count *decorative* volumetric facets, a floating base and luminous concentric rings, with colors keyed to the existing public root palette.
- A static central multiring nucleus, atmospheric dust and a low-opacity perspective grid. All presentation geometry is deterministic and request-free, and renders only on real WebGL availability.
- Real semantic node selection, approved public reviewed edges, date replay, accessible native index, editorial contextual inspector and local filters remain on the unchanged evidence model.
- Project search and layer toggles hide all corresponding decorative clusters together with the approved root. Three.js GPU resources are disposed on non-BFCache page exit/context loss, including Points geometry and materials.
- The UI visibly distinguishes decorative towers/dust from source-backed structure. **Decorative facets are never graph nodes, linked dependencies, component counts, live activity, deployment events or features.**

## Safety/architecture boundaries

The pure, bounded `src/v5/atlas-architecture.mjs` accepts only a validated graph with exactly eight public catalog roots and their finite positions. Unsupported/private/duplicate root identities produce no decorative clusters. It introduces no provider source, API, credential, database mutation, persistence, tracking or animation timer.

The visual core is an optional Three.js enhancement. No-JS/no-WebGL public semantic navigation is unchanged. No private Knowledge records are fetched or made public.
